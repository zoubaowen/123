# 学生六大创作入口大师 Skills 设计

## 目标

为学生编程工具的六个创作入口提供六个内置、大师级 Skill。学生提出要求后，Skill 只追问真正影响结果的 2–4 个关键问题，其余专业判断、工具执行、质量检查、修改和成果交付由 Skill 主动完成。

学生可以看见正在使用的 Skill 和创作阶段，但不需要理解 Skill 安装、MCP、模型或接口配置。

## 范围

| 学生入口 | 内置 Skill | 核心成果 |
| --- | --- | --- |
| 画一张图 | `student-image-master` | 可查看、可修改的图片作品 |
| 做一段视频 | `student-video-master` | 角色一致、故事连贯的视频成片 |
| 创作音乐 | `student-music-master` | 可播放的音乐作品；工具未接入时不得宣称已生成音频 |
| 做小游戏 | `scratch-game-coach`（大师级升级） | 可运行、可玩的游戏项目 |
| 写作表达 | `student-writing-coach`（大师级升级） | 保留学生表达的完整作品 |
| 学习辅导 | `student-learning-master` | 分步学习过程、练习与理解复盘 |

本设计优先完成 Skills、入口映射、流程状态和质量门禁。视频生成工具后续接入火山引擎；音乐通过统一适配接口接入未来选定的服务。

## 方案选择

采用“六个独立大师 Skill + 显式入口映射”。不依赖模型根据描述猜测应使用哪个 Skill，也不引入第一版不需要的总导演 Skill。

入口映射是唯一事实来源。点击入口时，前端同时设置学生起始请求和对应 Skill；创建任务时将该 Skill 写入 `skillList`，服务端沿用现有初始化与加载机制将 Skill 放入任务环境。

## 大师 Skill 统一契约

每个 Skill 必须明确实现以下阶段：

1. `discover`：理解需求，只询问 2–4 个关键问题。
2. `plan`：形成适合该领域的专业方案，并用儿童能理解的语言说明。
3. `produce`：调用可用工具制作真实成果，不用文字冒充工具产物。
4. `inspect`：依据领域质量量表检查成果。
5. `revise`：定位问题并尽量局部重做，保留已确认成果。
6. `deliver`：交付可使用的作品、简短说明和继续修改方式。
7. `reflect`：告诉学生本次使用的方法和学到的知识。

共同规则：

- 能安全推断的细节由 Skill 自动决定，避免把流程变成长问卷。
- 每一阶段说明“正在做什么”和“为什么”，不展示内部系统提示词。
- 工具不可用或失败时说明真实状态，保留中间成果，并给出恢复方式。
- 未通过领域质量门禁不得宣称完成。
- 内容必须适龄、安全，不诱导学生公开个人信息或接入不受控的外部账号。
- 写作和学习不得替学生完成应由其独立完成的作业。

## 六个 Skill 设计

### 绘画大师

关键输入包括主题、用途、画幅、风格和主体。Skill 先形成视觉方案，再调用现有 `ImageGen` / `ImageEdit` 工具。质量检查覆盖构图、主体完整性、角色一致性、文字准确性、画面可读性和儿童内容安全。修改优先采用局部编辑，并支持同一方案的多版本比较。

### 视频大师

关键输入包括主题、观众、时长、画幅和表达目标。火山引擎视频工具接入后，由 Skill 负责从策划到成片的完整执行。

以下是不可跳过的硬性门禁：

1. **角色设定锁定**：记录姓名、年龄、外貌、服装、配色、道具、性格和不可变化特征。
2. **角色一致性参考图**：生成多角度、多表情参考；学生确认后锁定为所有镜头的共同参考。
3. **故事连续性表**：逐镜记录时间、地点、人物状态、道具位置、动作承接、情绪和光线。
4. **九宫格分镜**：每格记录景别、构图、动作、台词或旁白、时长、运镜和转场。超过九个镜头时使用多页九宫格，不压缩或跳过镜头。
5. **生成前一致性检查**：检查角色、服装、场景、道具、光线和故事因果。
6. **逐镜生成**：每个镜头继承角色参考、视觉风格锚点和连续性表。
7. **粗剪检查**：识别角色漂移、动作跳跃、场景突变、叙事断裂和节奏问题。
8. **局部返工**：只重做问题镜头，并同步更新连续性表。
9. **成片门禁**：字幕、声音、比例、时长、故事连贯性、角色一致性和内容安全全部通过后方可交付。

前端必须在“角色参考确认”和“九宫格分镜确认”两个节点等待学生确认，其余步骤可以自动推进。

### 音乐大师

关键输入包括用途、情绪、风格、时长、速度和是否需要人声。Skill 产出曲式、歌词、配器和生成参数，并通过工具无关的音乐适配接口执行。质量检查覆盖曲式完整性、旋律与节奏一致、歌词安全、音质、时长和用途适配。音乐服务尚未配置时，可以完成策划和生成参数，但必须明确标记“尚未生成音频”。

### 游戏大师

关键输入包括主题、玩家目标、操作方式、胜负规则和难度。Skill 先完成最小可玩版本，再运行并检查操作、碰撞、计分、胜负、重开和异常路径。核心玩法通过后，才增加关卡、美术和音效。交付物必须可以运行和实际游玩。

### 写作大师

关键输入包括文体、主题、读者、篇幅和学生已有想法。Skill 使用提问、结构、示例和逐段反馈帮助学生完成作品，保留学生自己的措辞与观点。质量检查覆盖主题、结构、逻辑、语言、事实、年龄适配和原创参与度。

### 学习大师

关键输入包括学科、年级、知识点和卡住的位置。Skill 先诊断已有理解，再用问题、例题、图示或小实验分步引导。每一步等待学生作答并检查理解，最后提供针对性练习、纠错和复盘。需要专科能力时可以建议已有数学、英语、科学或编程 Skill，但本入口始终由 `student-learning-master` 维护统一学习流程。

## 学生可见体验

点击创作入口后，编辑框获得起始请求，同时显示对应大师卡片。卡片包括：

- 大师名称与一句话能力说明。
- 当前阶段和七阶段进度。
- 当前需要学生回答或确认的内容。
- 已完成的中间成果，例如视觉方案、角色参考、九宫格、游戏试玩或写作结构。
- 工具不可用时的明确状态和后续恢复入口。

学生不直接编辑 `skillList`，也不看到 MCP、密钥或供应商配置。教师和管理员可以在管理界面查看启用情况和服务可用性。

## 数据流

1. 学生选择创作入口。
2. `StudentCapability` 映射到唯一 Skill 名称和起始请求。
3. 前端保存选中 Skill，并在创建任务时写入 `skillList`。
4. 现有任务 API 保存 Skill 配置。
5. Agent 启动时，现有 Skill 初始化器将内置 Skill 放入任务环境。
6. Agent 按 Skill 契约执行并通过现有消息流回传阶段、确认请求、工具结果和成品。
7. 前端将结构化阶段显示为学生可见的大师流程卡。

第一版可从消息中的约定阶段标记生成流程卡；如验证发现解析不稳定，再升级为共享结构化事件类型，不提前扩展协议。

## 工具边界

- 图片使用现有 `ImageGen` 和 `ImageEdit`。
- 游戏使用现有文件、命令、预览和部署能力。
- 写作与学习使用模型、文件和已有学科 Skills。
- 视频 Skill 依赖后续火山引擎适配工具；凭证只保存在服务端环境中。
- 音乐 Skill 依赖统一音乐生成接口，具体供应商后续决定。
- Skill 不直接读取、输出或记录任何密钥、Token 或服务端敏感配置。

## 错误处理

- Skill 不存在或初始化失败：阻止任务启动并给出可恢复提示，不静默退回普通提示词。
- 生成工具不可用：保留策划与中间成果，显示缺少的能力，不伪造链接或成品。
- 单个生成步骤失败：最多进行受控重试，仍失败则停在该阶段并允许继续。
- 视频单镜头失败：仅重做该镜头；不得丢失角色参考、九宫格和连续性表。
- 学生取消或修改目标：保留已确认内容，重新规划受影响的后续阶段。

## 测试与验收

### Skill 文件验证

- 六个映射目标均存在并能被现有 Skill Loader 解析。
- 名称、描述和触发范围无冲突。
- 每个 Skill 都包含统一七阶段和领域质量量表。
- 视频 Skill 明确包含角色参考图、连续性表、九宫格和两个学生确认门禁。

### 前端与数据流验证

- 六个入口各自映射唯一 Skill。
- 选择入口后，大师卡片和起始请求同步变化。
- 创建任务时对应 Skill 出现在 `skillList` 中。
- Skill 初始化失败时有明确错误状态。
- 流程卡能展示阶段、确认点、中间成果和完成状态。

### 端到端验收

- 图片：完成生成、质量检查和一次局部修改。
- 视频：完成角色参考、九宫格、多镜头生成、连续性检查和问题镜头返工；工具接入前以受控测试替身验证契约。
- 音乐：验证未配置供应商时不会宣称已生成音频；接入后完成生成和一次修改。
- 游戏：生成可运行作品并通过核心玩法检查。
- 写作：学生参与完成结构和修改，不直接代写。
- 学习：诊断、引导、检查理解和练习闭环完整。

## 实施顺序

1. 建立统一 Skill 质量契约与验证测试。
2. 新增绘画、视频、音乐和学习四个 Skill，升级游戏与写作两个 Skill。
3. 建立六入口到 Skill 的显式映射，并把选中 Skill 传入任务创建数据。
4. 增加学生可见的大师流程卡和确认节点。
5. 验证现有图片、游戏、写作与学习流程。
6. 建立火山引擎视频工具适配并进行真实端到端验收。
7. 选定音乐服务后接入统一适配接口并验收。

## 非目标

- 第一版不提供学生自行安装、删除或编辑 Skills。
- 第一版不让学生接触 API Key、MCP 或供应商配置。
- 第一版不建立复杂的多 Skill 总导演或自治子 Agent 系统。
- 在视频或音乐工具尚未接入时，不用模拟链接、占位音视频或文本说明冒充真实成品。
