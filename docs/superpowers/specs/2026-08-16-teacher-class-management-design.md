# 教师端班级管理设计

## 目标

将 `/teacher/classes` 从建设占位页升级为教师真实可用的班级管理入口，让老师能够快速了解负责班级、课程进度、学生状态，并从班级详情直接进入课堂准备流程。

本阶段使用类型明确的演示数据，不新增后端接口，不提供无法持久化的新增、编辑或删除按钮。

## 用户与使用场景

主要用户是机构授课老师。核心场景为：

1. 老师进入班级管理，查看自己负责的全部班级。
2. 老师通过名称或课程关键词筛选班级。
3. 老师进入班级详情，查看课程进度、学生名单和近期课堂情况。
4. 老师从班级详情选择下一课节，进入现有“开始上课”配置流程。
5. 老师随时返回班级总览或教学首页。

## 范围

### 本阶段实现

- 班级总览页：班级数量、学生总数、平均进度和待点评数量。
- 班级卡片：班级名称、关联课程、学生人数、课程进度、完成率和下一课节。
- 搜索与状态筛选：支持按班级名、课程名筛选，并区分全部、进行中和已结课。
- 班级详情页：班级概况、课程进度、下一课节、学生名单、近期课堂记录。
- 学生名单：姓名、学习状态、任务完成数、最近活跃时间和需要关注标记。
- 课程进度：按课节展示已完成、下一节和未开始状态。
- 开始上课：复用现有 `StartClassDialog`、课堂状态仓库和 `/teacher/classroom/active` 页面。
- 空结果与异常状态：搜索无结果时展示可恢复的空状态；无效班级 ID 返回班级总览。
- 小宝角色：继续使用 `@ai-xiaobao/chat-core` 中九宫格标准角色资产。

### 本阶段不实现

- 新建、编辑、删除班级。
- 批量导入学生、调班、退班。
- 真实数据库持久化和机构权限控制。
- 家长信息、收费、续费与教务排课。
- 学生详情编辑和成绩导出。

这些操作必须等机构管理后端与权限模型建立后再实现，避免出现无法保存的假功能。

## 信息架构

### `/teacher/classes`

页面从上到下包含：

1. 标题区：班级管理说明和返回教学首页入口。
2. 数据摘要：负责班级、学生总数、平均课程进度、待点评作品。
3. 搜索与状态筛选。
4. 响应式班级卡片网格。
5. 小宝教学提示：提示近期需要关注的班级，不遮挡主要内容。

班级卡片的主操作为“查看班级”，下一课节存在时提供次级“准备上课”入口。页面不显示新增班级等不可用按钮。

### `/teacher/classes/:classId`

页面由以下区域组成：

1. 面包屑与班级标题。
2. 班级概况与下一课节卡片。
3. 课程进度时间线。
4. 学生名单表格。
5. 近期课堂记录与小宝教学建议。

“开始上课”使用当前开课配置弹窗；确认后更新共享教师课堂状态并进入 `/teacher/classroom/active`。

## 视觉与交互

- 继续沿用教师端蓝白配色、圆角卡片、轻边框与紧凑数据密度。
- 主要操作保持蓝色填充按钮，次要操作使用描边或文字按钮。
- 不使用 emoji、临时插画或自制 SVG；图标使用 Lucide，小宝使用生产角色资源。
- 1440×900 下展示三列班级卡片，1366×768 下至少两列；较窄桌面允许单列，不产生横向滚动。
- 学生名单在桌面端使用表格；窄屏下允许容器横向滚动，但页面本身不横向溢出。
- 搜索和筛选即时更新演示数据，不触发网络请求。

## 数据模型与组件边界

扩展教师领域类型：

- `TeacherClassStatus`：`active | completed`。
- `TeacherStudentSummary`：学生身份、状态、任务进度和最近活跃时间。
- `TeacherLessonProgress`：课节顺序、状态和完成信息。
- `TeacherClassDetail`：班级摘要、学生名单、课节进度和课堂记录。

数据仍集中在 `demo-data.ts`，纯查询逻辑放入独立模块，避免把筛选和查找规则写进页面组件。

建议组件：

- `TeacherClassesPage`：页面编排、搜索和筛选状态。
- `TeacherClassCard`：单个班级摘要及导航操作。
- `TeacherClassDetailPage`：详情编排和开课入口。
- `TeacherStudentRoster`：学生名单展示。
- `TeacherLessonProgressList`：课节进度展示。

共享课堂状态继续由 `TeacherWorkspaceProvider` 管理，班级页面不复制新的课堂状态。

## 数据流

1. 页面从教师演示仓库读取班级列表或详情。
2. 搜索和筛选通过纯函数返回派生列表，不修改源数据。
3. 点击班级卡片进入 `/teacher/classes/:classId`。
4. 点击开始上课时，根据班级下一课节生成 `StartClassInput`。
5. 确认后调用现有 `startClass`，成功后进入活动课堂。
6. 结束课堂后仍回到教学首页，课堂记录写入当前教师上下文。

## 错误与边界处理

- 搜索无结果：展示“没有找到班级”，并提供清除筛选按钮。
- 无效班级 ID：重定向到 `/teacher/classes`，不展示空白页。
- 班级已结课：不显示开始上课按钮。
- 已有课堂进行中：沿用 `startClass` 的保护，不允许开启第二个课堂。
- 下一课节缺失：只显示课程完成状态，不构造无效开课数据。

## 测试与验收

- 纯函数测试：班级关键词和状态筛选、班级详情查找。
- 页面静态测试：摘要指标、班级卡片、学生名单、课节进度、无结果状态。
- 路由测试：班级列表和详情路由均已注册，无效 ID 能安全返回。
- 回归测试：现有教师工作台、开课、活动课堂和学生创作平台测试继续通过。
- 必须执行：`pnpm.cmd --filter @ai-xiaobao/web test`、`pnpm.cmd type-check`、`pnpm.cmd lint`、`pnpm.cmd --filter @ai-xiaobao/web build`。

## 完成标准

- 老师可以从教师导航进入真实班级总览，而不是建设占位页。
- 老师可以筛选班级并进入任一有效班级详情。
- 班级详情清楚展示学生名单、课节进度和近期课堂记录。
- 下一课节可以连接现有开课配置与活动课堂流程。
- 页面不存在暗示已经支持持久化管理的假按钮。
- 学生端和 `/admin` 平台管理端没有被混入教师班级页面。
