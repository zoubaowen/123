# AI小宝学院品牌与小宝角色系统设计

## 1. 目标

将项目的对外品牌统一为“AI小宝学院”，并把“小宝”从单一吉祥物升级为贯穿登录、课程、聊天、任务和成长体系的动态 AI 伙伴。

首阶段必须交付一个可实际使用的品牌版本，而不是只有概念图：统一角色组件、九套课程装扮、动态登录体验以及可扩展的宠物状态模型。后续页面和节日皮肤复用同一套规范。

## 2. 范围拆分

### 第一阶段：品牌基础与可用角色

- 统一所有用户可见名称、标题、安装程序信息和主要文档为“AI小宝学院”。
- 建立小宝唯一基础形象与九套课程装扮。
- 重构统一的小宝角色组件，支持装扮、情绪、动作和尺寸。
- 打磨登录页，并让小宝对输入、等待、成功和失败产生动画反馈。
- 在首页、启动页、聊天头像、加载、空状态和任务完成等关键位置接入小宝。
- 建立宠物系统的数据结构和最小可用交互。

### 第二阶段：成长、节日与全页面铺设

- 等级、经验、心情、亲密度、连续学习天数和装扮收藏。
- 课程进度驱动的小宝成长反馈。
- 节日、季节、昼夜和特殊活动装扮。
- 个人中心的衣橱、互动和成长记录。
- 管理端的皮肤启用、时间窗口和课程绑定配置。

## 3. 品牌命名规则

### 必须统一

- 用户界面：`AI小宝学院`，不插入空格。
- 中文产品描述：`青少年 AI 编程创作伙伴`。
- 英文机器标识：`ai-xiaobao-academy`。
- 安装包和可执行文件：保持 ASCII，例如 `AI-XiaoBao-Academy`，避免 Windows 路径和更新器兼容问题。
- 新增内部包命名空间：优先使用 `@ai-xiaobao/*`。

### 不做无意义替换

- 第三方仓库地址、历史设计文档中的来源引用和兼容协议名称保留原名。
- CloudBase、OpenCode、CodeBuddy 等技术或供应商名称保留。
- 迁移 `@ai-xiaobao/*` 时一次性修改 package manifests、导入、路径别名、构建脚本和锁文件，不能只替换显示文字。
- 不把真实磁盘仓库目录强行改成中文路径；仓库显示名和发布物统一即可。

## 4. 小宝核心身份

### 永久基础形象

采用第三套九宫格第二排中间作为核心参考：

- 深蓝色五角星形头罩，金色内轮廓。
- 深蓝脸部区域和明亮大眼睛，保留金色眉毛。
- 奶油白学院制服，深蓝与金色为主要品牌色。
- 内侧带代码符号和星光纹样的短披风。
- 悬浮创作笔作为主要道具。
- 整体聪明、勇敢、亲切，适合 8–18 岁，不做幼儿化宠物。

无论课程装、节日装或成长形态如何变化，都必须保留至少四个识别锚点：星形轮廓、深蓝脸部、金色眉毛、星光/代码披风。

### 性格

- 像可靠的同龄学长，而不是老师或婴儿宠物。
- 鼓励探索，不讽刺错误，不代替学生思考。
- 工作时专注，成功时有感染力，失败时给出温柔且具体的下一步。
- 语言简洁、有活力，不过度使用幼儿语气词。

## 5. 九套首发课程装扮

九宫格中的造型被解释为同一个小宝的不同身份，而不是九个角色。

1. 星光院长：默认品牌形象，学院制服、星光披风、悬浮创作笔。
2. 编程魔法师：代码符号披风、键盘光效、终端粒子。
3. AI 探索家：数据星图、模型节点徽章、青蓝光环。
4. 绘画设计师：调色笔、色彩披风边缘、画布粒子。
5. 音乐创作家：音符耳饰、节拍光环、小型合成器道具。
6. 科学实验员：护目镜、实验徽章、分子与轨道粒子。
7. 机器人建造师：工具背包、机械手套、零件光点。
8. 阅读学习官：书页披风、知识卡片、温暖阅读灯光。
9. 冒险成长版：轻便背包、成就徽章、升级星轨。

课程装扮只改变服装层、道具层和特效层，不改变基础头脸比例。

## 6. 角色组件架构

建立单一公共组件 `XiaoBao`，由配置驱动：

```ts
type XiaoBaoOutfit =
  | 'academy'
  | 'coding'
  | 'ai'
  | 'art'
  | 'music'
  | 'science'
  | 'robotics'
  | 'reading'
  | 'adventure'

type XiaoBaoMood = 'idle' | 'happy' | 'thinking' | 'working' | 'excited' | 'sleepy' | 'comforting'
type XiaoBaoAction = 'breathe' | 'blink' | 'wave' | 'write' | 'celebrate' | 'upgrade' | 'sleep'
```

渲染层顺序固定为：背景光效、披风、身体、服装、脸部、道具、前景粒子。所有实例共用基础 SVG 骨架，装扮通过分层 SVG/CSS 组合，宣传图可以使用高质量栅格资产。

组件必须支持：

- `outfit`、`mood`、`action`、`size`、`interactive`。
- `prefers-reduced-motion`，关闭非必要动画。
- 语义化 `aria-label`，装饰性实例可隐藏。
- 动画不会阻塞输入和页面导航。
- 小尺寸仍可识别，不依赖细小文字或复杂纹理。

## 7. 动画规范

基础动画采用 CSS/SVG，不引入沉重运行时：

- 待机：3–4 秒轻微呼吸，随机眨眼。
- 挥手：0.8–1.2 秒，可循环一次。
- 思考：眼神移动、创作笔绕行、小星点聚集。
- 工作：创作笔书写、代码粒子出现，不做连续大幅抖动。
- 成功：跳跃一次、披风展开、星光爆发。
- 失败：短暂低头后恢复并给出安慰动作，不表现惩罚或沮丧过度。
- 睡眠：夜间或长时间无操作时降低亮度、缓慢呼吸。

动画状态由业务事件触发，不能依赖页面组件各自拼接 class 名。

## 8. 动态登录页

登录页以小宝为视觉中心，但表单始终保持清晰和可操作：

- 初次进入：小宝从柔和星光中出现并挥手。
- 聚焦账号：小宝看向输入框。
- 聚焦密码：小宝用披风或双手遮眼，不遮挡表单。
- 提交中：创作笔围绕小宝书写星轨，按钮显示明确加载状态。
- 登录成功：小宝跳跃庆祝，随后进入主页。
- 登录失败：小宝做安慰动作，同时显示可读错误信息。
- 注册/短信流程：发送验证码时展示信封或星光传递动作。

桌面与网页共用同一逻辑；窄屏上下布局，宽屏采用角色区与表单区双栏布局。

## 9. 宠物系统

### 最小数据模型

```ts
interface XiaoBaoPetState {
  level: number
  experience: number
  mood: 'happy' | 'focused' | 'curious' | 'sleepy'
  affinity: number
  streakDays: number
  selectedOutfit: XiaoBaoOutfit
  unlockedOutfits: XiaoBaoOutfit[]
  lastInteractionAt: string
}
```

### 成长来源

- 完成课程和作品获得经验。
- 连续学习、主动修改作品和完成挑战增加亲密度。
- 不通过付费或重复点击制造虚假成长。
- 不因中断学习扣除等级或惩罚用户。

### 第一阶段交互

- 点击小宝触发问候或随机动作。
- 完成任务触发庆祝并获得经验。
- 达到等级阈值解锁一套课程装扮或徽章。
- 个人中心可以选择已解锁装扮。

## 10. 自动换装优先级

从高到低：

1. 用户手动选择并锁定的装扮。
2. 当前课程绑定的装扮。
3. 限时节日或活动装扮。
4. 昼夜和季节装饰。
5. 默认星光院长装。

时间和节日只能添加服饰/特效层，不能替换小宝的核心身份。

## 11. 页面铺设原则

- 首页：完整小宝主视觉和课程装扮入口。
- 启动页：轻量呼吸、眨眼和星光动画。
- 登录页：完整情境动画。
- 聊天：头像、思考、工作、完成状态。
- 任务列表：只在空状态、进度节点和完成反馈使用，避免每张卡片重复堆叠。
- 课程页：每门课程使用对应装扮。
- 错误页：安慰动作和解决建议，不用哭泣角色制造焦虑。
- 个人中心：宠物成长、衣橱与成就主入口。

“铺满项目”指形成统一陪伴体验，不是每个角落都塞入角色。信息密集页面优先保证内容可读性。

## 12. 数据与兼容性

- 宠物状态通过现有 Repository 抽象持久化，CloudBase 与 Drizzle 两种 provider 都要实现。
- 未登录用户使用本地默认状态，登录后按明确规则合并，避免覆盖云端成长记录。
- 老用户没有宠物记录时自动创建默认状态。
- 新字段和环境变量必须同步到示例配置与迁移文件。

## 13. 验证标准

- 所有用户可见主品牌均显示为“AI小宝学院”。
- 九套装扮在 48px、120px 和主视觉尺寸下仍能识别为同一个小宝。
- 登录页的六种状态都有明确视觉反馈，键盘操作不受影响。
- 减少动画模式下页面仍完整可用。
- 宠物经验和装扮解锁在两种数据库 provider 下行为一致。
- 类型检查、格式检查、Lint、构建和相关测试通过。
- Windows 安装包名称、窗口标题、图标和更新信息一致。
- 日志只使用静态字符串，不输出用户、路径、状态数值或敏感配置。

## 14. 非目标

- 第一阶段不做复杂 3D 模型、骨骼引擎或实时语音口型。
- 不一次性制作所有节日皮肤；先建立可扩展机制和一套示例。
- 不把课程内容、计费或账号系统整体重写。
- 不删除历史来源和第三方兼容信息。

## 15. 实施顺序

1. 品牌引用盘点和安全改名。
2. 小宝视觉规范、基础骨架和九套装扮配置。
3. 动画状态控制与可访问性。
4. 动态登录页。
5. 首页、启动页、聊天和关键状态接入。
6. 宠物数据模型、持久化和最小交互。
7. 课程/节日换装机制。
8. 全量验证与 Windows 发布物检查。
