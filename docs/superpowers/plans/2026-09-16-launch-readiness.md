## 二、环境与凭据（⛔ 全部卡在你这里）

| 项 | 需要什么 | 备注 |

| 媒体能力（图片/视频） | 真实媒体服务 + 凭据 | 不接就应在产品上**明确不开放**这些能力 |

### ⚠️ 上线前最大的技术风险

**CloudBase 版仓储从未连过真实 CloudBase 环境**：全部实现都只在假数据库（`FakeCloudBaseDatabase`）上测过。
`drizzle` 版则在真实 SQLite 上跑过集成测试。所以：

- 若生产用 `cloudbase`，上线前**必须**在一个真实 CloudBase 环境做一次冒烟：
  集合是否齐（`cloudbase/client.ts` 有集合清单）、安全规则、显式翻页在真实数据量下的表现、索引/权限。
- 若生产用 `drizzle`，需要明确数据落在哪台机器的哪个文件上、备份与并发写方案。

## 八、最短上线路径（建议）

1. 你确认**范围**（内部灰度 / 对外）+ **目标环境**（CloudBase 环境 id 与 provider）+ 上表凭据；
2. 我做完 Task 4–6（约 3–4 轮）→ 教师端闭环功能完整；
3. 我在**真实 CloudBase 环境**跑一次冒烟（集合、安全规则、显式翻页、迁移落库）并修掉问题；
4. 生产构建 + HTTPS + 生产密钥，按第四节补最小可用的备份与监控；
5. 明确媒体/Redis/并发是否进这一次上线；不进就写在发布说明里。
